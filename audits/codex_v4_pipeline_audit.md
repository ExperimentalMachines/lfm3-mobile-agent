Ranked defects:

1. **P1 — Gate passes with zero correct answers and also accepts missing evaluation inputs.** `scripts/v4_gate.py:54–64`, against `docs/PREREG_v4.md:34–36`. **Failing input:** all 116 real task names with synthetic outcomes (3 answer successes; 10 action successes in both arms), 200 wrong answer predictions, and 200 completion predictions. Result: `dev_answer_exact=0.0`, `PASS=true`; `correct` never enters the gate. A separate test with empty `dev_complete`, an empty v3 directory, and fabricated task names also passes. `aw()` combines every `run_*` directory and validates neither task identities nor seed/model identity. **Fix:** require the preregistered exact-match criterion, complete predictions against frozen dev keys/GT, and one complete, identified seed-30 run for each model. Record the numerical “clearly above 0” threshold before selection; return failure status when the gate fails. [Complete-input reproduction](v4_pipeline_audit/gate_zero_accuracy_complete_inputs.json), [missing-input reproduction](v4_pipeline_audit/gate_false_pass.json).

2. **P1 — “Sealed” logs expose per-task outcomes after every episode.** `scripts/local_sealed_aw.sh:14,38`; `android_world/android_world/suite_utils.py:417,728`. **Failing input:** the actual `process_episodes()` function, supplied two synthetic episodes, prints a table containing task names and `mean_success_rate`; the exact shell filter preserves it. Removing “Task Successful/Failed” lines does not remove these tables or exception diagnostics. **Fix:** capture full output inside the sealed directory and expose only explicitly generated progress counts; disable outcome summaries in the progress channel. Do not inspect existing sealed logs to test this. [Surviving table](v4_pipeline_audit/sealed_filter_synthetic.txt).

3. **P1 — Teacher verification accepts substantively different answers.** `data/vm_v4_teacher.py:82–95`. **Failing inputs:** `agree("1.5", "15")`, `agree("$10", "€10")`, `agree("-5", "5")`, `agree("100", "1000")`, and `agree("available", "unavailable")` all return `True`. Punctuation stripping destroys decimals/time structure; numeric comparison discards signs/currencies; substring matching admits partial and opposite answers. **Fix:** use exact normalized text for phrases and typed numeric comparisons preserving decimal value, sign, unit, and currency. Case normalization must depend on the answer type. Reject mismatches instead of accepting containment. [Executable cases](v4_pipeline_audit/teacher_rules.json).

4. **P1 — ScreenQA shortening can corrupt answers or abort the post-teacher build.** `data/vm_v4_teacher.py:181–185`; `data/v4_build_parquet.py:129–136`. **Failing input:** real row `data/train-00000-of-00016.parquet#219`, answer `10:49 PM on Jan 31, 2017`, shortened to `10:49 PM on Jan 31 2017`. The teacher accepts it; the unmodified builder raises `AssertionError` because its raw substring test differs. Independently, `1.50 → 150` is teacher-accepted, and `unavailable → available` passes both policies. **Fix:** share one conservative validator between producer and consumer; preserve numbers/negation and require a semantically complete answer span. Validate labels before starting the full build. [Real-row failure](v4_pipeline_audit/builder_and_guards.json), [teacher-loop corruption](v4_pipeline_audit/teacher_loop_repro.json).

5. **P1 — The verified question is not the question used for question-kind training rows.** `data/vm_v4_teacher.py:148–159`; `data/v4_build_parquet.py:70–81,143–149`. **Failing input:** a valid `question="What is the destination?"`, answer `Lyon`, and `direct_question="In the WRONG app, is the destination Lyon?"` are accepted. Verification sees only `question`; the answer-containing, wrong-app `direct_question` becomes the training goal. The same unchecked path affects 522 selected candidates. An embedded newline in `direct_question` also passes teacher field validation but produces `ValueError: unexpected user text layout` during building. Prefix actions/intents remain unchanged: all 13,333 copied prefix targets in the full test retain their original supervision. **Fix:** build and validate the exact eventual goal before verification; check its app/search constraints and answer leakage, normalize/reject newlines, and verify that the retained navigation prefix serves that goal. [Acceptance evidence](v4_pipeline_audit/teacher_loop_repro.json), [formatter failure](v4_pipeline_audit/verification.json).

6. **P1 — The AndroidWorld-app guard leaks known excluded apps.** `data/v4_select.py:29–34,70–73`. **Failing inputs:** selected training episodes `androidcontrol/815`, `/18012`, `/2080`, `/13527` open **Settings** in their history; sampled current actions contain no `open_app`, so `apps=[]` and selection accepts them. The denylist also misses seven of the 30 display names, including Maps, Phone, and Gmail; 87 selected episodes explicitly reference omitted display names through sampled/history app actions. Conversely, “kitchen drawers” in Houzz matches `draw` and is excluded. **Fix:** resolve episode-wide app identities from source metadata/full histories, compare package IDs and explicit aliases, and fail closed on unknown provenance. Avoid substring tests on arbitrary goal prose. Evidence establishes same-app exposure; it does not establish copied benchmark tasks. [Exact candidates and counts](v4_pipeline_audit/selection.json).

7. **P1 — Failed AndroidWorld runs are reported as finished.** `scripts/local_sealed_aw.sh:6,36–40`; `scripts/local_v4_to_aw.sh:5,24–34`. **Failing input:** the unmodified sealed script executed with local command stubs and a runner exiting `42` returns `0` and prints `SEALED v1_seed7 AndroidWorld finished`. The development handoff explicitly trusts that marker. Neither wrapper verifies completion or implements the preregistered single retry for infrastructure failures before step 1. Startup health loops can also wait forever after server failure. **Fix:** preserve runner exit status, validate the full episode inventory before emitting a success marker, implement the narrowly permitted retry, and bound server startup with PID-aware cleanup. [Actual wrapper reproduction](v4_pipeline_audit/runner_cache_repro.json).

8. **P2 — `PROMPT_ARGS` can silently reuse results generated with the old prompt.** `scripts/vm_model_pipeline.sh:104,131–134,158–162,176–180`. **Failing input:** existing predictions and a manifest with `prompt="v1"`, otherwise matching model path/image budget/thinking settings. Both production AC/dev skip checks return success even when `PROMPT_V4_POOL` is now requested; `generate.py` never runs, so its stronger manifest check cannot help. **Fix:** bind cache acceptance to prompt/pool hash, dataset revision, model fingerprint, and complete key sets; apply this to dev scoring too. Use fresh output identities after any change. [Reproduction](v4_pipeline_audit/runner_cache_repro.json).

9. **P2 — Teacher checkpointing loses work on restart and does not cover ScreenQA incrementally.** `data/vm_v4_teacher.py:114–125,171–192`. **Failing input:** with `save_every=1`, the actual loops save QA, then process all eight synthetic ScreenQA rows without another save until the final call. Production has 5,995 ScreenQA rows. Restart always initializes empty dictionaries, and a simulated transient upload error escapes `save()` and stops processing. Local persistence happens first, but no restore path consumes it. **Fix:** save atomically during both phases, persist processed/rejected keys and input identity, restore compatible checkpoints, and retry upload separately from local progress. [Save schedule](v4_pipeline_audit/teacher_loop_repro.json), [upload failure](v4_pipeline_audit/extra_probes.json).

10. **P2 — Training inventories change within an episode; offline inventories depend on the gold action.** `data/v4_build_parquet.py:85–89`; `train/agent_format.py:110–119`; `eval/androidcontrol/generate.py:80–88`. **Failing input:** episode `androidcontrol/17782` includes FitAI initially, then loses it after `open_app` leaves the eight-step history; distractors change too. There are 1,042 episodes with changing inventories. Offline rewriting similarly inserts the gold current `open_app` target, while AndroidWorld receives a fixed device inventory. **Fix:** create one stable episode inventory from episode-level app provenance and use it on every row, including QA copies; make offline inventory availability independent of the current label. [Examples](v4_pipeline_audit/prompt_lists.json).

11. **P2 — The history check does not establish the claimed coverage.** `data/v4_select.py:60–65`. **Failing input:** a final row at step 3 with history containing only `3. ...` passes the actual selector. Current selections include 544 histories truncated to eight steps, 2,971 episodes with missing sampled rows, and 176 terminal-only episodes. Eight-step truncation matches inference, but these counts do not support the documented “full history”/“complete, contiguous episodes” claim. **Fix:** validate the entire expected rolling-window index sequence; explicitly declare step sampling, or recover missing prefix rows if full trajectories are required. Preserve the intended inference history window. [Gap reproduction](v4_pipeline_audit/builder_and_guards.json), [actual counts](v4_pipeline_audit/selection.json).

12. **P2 — Dev provenance and completion controls diverge from the stated protocol.** `data/v4_select.py:44,93–103`; `data/v4_build_parquet.py:115–127`; `docs/PREREG_v4.md:47–48`. **Failing input:** all 941 source rows belonging to the 200 dev episodes have `split="train"`; none comes from AC val. Screen-disjoint removal protects the newly built v4 dataset, but these episodes were present in v3's training data. Also, 33 dev candidates are explicitly classified as information-seeking yet their original goals become `dev_complete` negatives; e.g. “Show me the currency exchange rates…” receives gold `complete`. **Fix:** use the preregistered val source or append a dated deviation before selection; do not describe these endpoints as held out from v3. Ensure completion controls are unambiguously action-only under `SYSTEM_PROMPT_V4`. [Split evidence](v4_pipeline_audit/selection.json), [actual dev goals](v4_pipeline_audit/smoke_inspection.json).
