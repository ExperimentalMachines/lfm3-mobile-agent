**GUI datasets for v4: adversarial viability audit**

Audit date: 2026-11-17. Decision scope: additions to LFM3-VL-2B under the remaining approximately 3.5 GPU-hours. **Recommendation: choose the NULL option. Admit zero rows from the nine listed releases for the next run.** Finish and validate v3, then spend the next training allocation on our own corrected histories, recovery, navigation-to-answer, and completion boundaries. This is a decision about incremental value and preparation cost, not a claim that all nine datasets lack useful content.

Three potentially useful findings survived scrutiny: GUI-Reflection really contains synthetic mistakes and recovery; Libra/Aguvis reasoning really can be joined to some of our selected steps; and Libra contains factual answers missing from raw AMEX terminal labels. None established an advantage over v3 plus the proposed targeted round under this budget. OS-Genesis has direct AndroidWorld contamination, the specified Android-Lab repository is empty, this AiTZ mirror contains original test data, and Mobile-R1's released typing payloads are systematically defective.

**Contract and contamination rules used in the decisions**

[train/agent_format.py](../../train/agent_format.py) supplies one current screenshot, a goal, and up to eight prior text intent/action pairs. Targets contain a short intent and one JSON action. The supported actions are `click`, `long_press`, `input_text`, `scroll`, `open_app`, `navigate_back`, `navigate_home`, `keyboard_enter`, `wait`, `answer`, and `status` with `complete`/`infeasible`. Points are integer coordinates in [0,1000]. There is no arbitrary drag, separate observation-memory tool, accessibility-tree input, or index-only click in this contract.

| Source operation | Exact conversion condition; reject when it fails |
|---|---|
| Pixel click / long press | Use actual image width/height, not a copied prompt resolution; normalize and round each coordinate to [0,1000]. Require a visible target. Do not silently clamp bad coordinates. |
| Already normalized point | Distinguish [0,1] from [0,1000]; multiply only the former. Require the source's current image to match the row. |
| SoM/index or bbox grounding | Resolve through original element bounds and verify the center on the raw current screenshot. An index alone is insufficient. Removing marked targets can remove information the source model had. |
| Type / write | [AW actuation](../../android_world/android_world/env/actuation.py) types **and presses Enter**. Keep only when this compound behavior is appropriate. Coalesce an immediately following equivalent submit/Enter, with the correct next state/history; drop a field-entry prefix when auto-submit would change later states. Never retain an extra Enter by default. |
| Swipe / scroll | Our executor swipes from the screen center toward an edge. Map **finger up → content down**, down → up, left → right, right → left, only when the source describes finger displacement. Do not invert an already content-oriented `scroll`. Reject sliders, drawing, edge pulls, regional carousels or swipes requiring a different origin. |
| Compound action / unsupported key | Do not collapse focus+type, multiple clicks, `clear`, arbitrary keys, or multi-call code into a single action without intermediate-state evidence. Cut the dependent suffix at the first unsupported transition. |
| Terminal | Require visible or logged state evidence that every requested operation is done. A model-authored success flag is not evidence. Failure is not automatically `infeasible`. |
| Factual response | Map to `answer(text)` only when the goal requests information and the answer is supported by the current screenshot or causally available text history. [Our AW agent](../../eval/androidworld/lfm_agent.py) ends the episode on `answer`; do not append a terminal row afterward. |
| Reasoning / history | Retain a short, grounded intent, not arbitrary long CoT. Rebuild history using only past information available to this executor. Dropping past images, trees, memory, or generated observations is lossy unless the target remains supported. Wrong past actions may be context, never successful-action targets. |

Contamination has three separate levels: shared app family; use of AW environment/task initialization; and duplication of benchmark goal templates/seeds. These must not be conflated. The exclusion list is Simple Calendar, Simple SMS, Simple Draw, Simple Gallery, Markor, Pro Expense, Broccoli, Joplin, OsmAnd, Retro Music, VLC, Tasks (`org.tasks`), Audio Recorder, and OpenTracks, including package variants. Representative package checks are `com.simplemobiletools.calendar.pro`, `com.simplemobiletools.smsmessenger`, `com.simplemobiletools.draw.pro`, `com.simplemobiletools.gallery.pro`, `net.gsantner.markor`, `com.arduia.expense`, `com.flauschcode.broccoli`, `net.cozic.joplin`, `net.osmand*`, `code.name.monkey.retromusic`, `org.videolan.vlc`, `org.tasks`, `com.dimowner.audiorecorder`, and `de.dennisguse.opentracks`.

Use the actual [v2 package rules](../../data/build_v2_mix.py), plus explicit package verification, not a name-only substring filter. Google Tasks is not automatically `org.tasks`; Android-Lab's Calendar is `com.skuld.calendario`, not Simple Calendar. Shared Settings/Clock/browser screens are not themselves proof of AW task leakage. All new episodes must also be disjoint from our dev/test episode IDs and images; unknown provenance is not evidence of cleanliness.

**Conversion and loss.** Original sampled rows have **2–5 images**, prior actions, optional memory, a thought, an action description, and an action. Keep the distinction even when the story sounds plausible. Verified official-train membership of the prefixes is narrower than corpus-wide split safety. Filename 15K/17K counts are approximate; the number that would survive one-image and executor screening is **UNVERIFIED**.

**Decision.** This is the best match for measured loops/no-ops and corrective intents, but the same construction on our already-selected AC rows avoids importing multi-image assumptions and mixed source histories. It does not provide our model's own failure-state distribution or calibrated completion. C1 is **VERIFIED for synthetic mistake/recovery content; CONDITIONAL for single-screenshot usability; UNVERIFIED for physical transition validity**. Allocate zero external rows.

**How to construct the targeted rows without repeating the v2 defects**

Use v3 as the rollout policy. Choose non-AW packages and independently authored tasks, such as suitable Android-Lab apps or a small controlled app collection, after package and task-template checks. Do not use AW task evaluators, AW snapshots, our failed AW episodes, or paraphrases of AW goals as training examples. Shared platform actions may be allowed explicitly, while AW third-party families remain excluded. Split by episode/task family and check screenshot duplicates before labeling.

For actual DAgger-style collection, run the policy in an environment and ask an expert for the next action **at the state it actually reached**, including its own textual history. If the model makes a wrong tap, the next screenshot must come from that wrong tap. Advancing to the next expert screenshot anyway is a static history perturbation, not an on-policy rollout. Keep failed/repeated actions in context and supervise only the expert correction; this trains loop escape without teaching the failed loop as the desired trajectory.

For own-AC synthetic rows, prefer observed repeated states and actions known to be ineffective. A guessed blank-area tap or an arbitrary scroll is not automatically a physical no-op. A wrong action that changes screens requires a real resulting state and verified recovery; do not paste the pre-error screenshot back after Back by assumption. Add the runtime-compatible `[no visible change]` feedback only when a comparable observation check supports it. No-op feedback also does not prove that an asynchronous action will never finish; include appropriate bounded waits where warranted.

Navigation-to-answer tasks must end with a verified factual `answer`, not silent completion. With one screenshot and short textual history, prefer questions whose answer is visible at the endpoint; earlier facts may be used only if causally preserved in history. Completion-boundary examples should pair visually similar incomplete and complete states, supervise the needed continuation on the former, and terminate only with actual goal-state evidence on the latter. Do not fabricate “infeasible” labels merely from an unsuccessful attempt.

**Nonempty-intent invariant: a build gate, not a best effort**

The current [v3 intent repair script](../../data/vm_v3_intents.py) fills current targets using templates/teacher output. Its apply path changes `messages[2].reasoning_content`; it does not reconstruct historical blank intents in the user message, and its remaining-blank count is not itself a fail-before-push assertion. That code observation does not establish how many blanks remain in the final, still-in-progress v3 artifact.

Before training v4, require all of the following on the **serialized final mixture**, after filtering, merging, and formatting:

- Every row, including `status` and `answer`, has a nonempty, non-whitespace current intent. Use one grounded sentence, usually 8–35 words and at most 200 characters; do not truncate away a negation or correction. Empty/placeholder teacher output fails the build. A deterministic truthful intent is acceptable for simple non-point actions.
- Every past action included in the up-to-eight-step history has a corresponding meaningful intent, and no future observation/answer is inserted into earlier history. Rebuild histories after type/submit coalescing or prefix truncation.
