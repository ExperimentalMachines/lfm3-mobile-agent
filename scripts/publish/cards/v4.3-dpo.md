# LFM3-VL-2B-AndroidAgent-v4.3-dpo

Round-5 candidate P: [v4.2](https://huggingface.co/alpharomercoma/LFM3-VL-2B-AndroidAgent-v4.2) trained to prefer the human step over **its own mistakes**. Learns from its own attempts: the contrast between its own wrong step and the right step at the same screen.

| | |
|---|---|
| Start | v4.2 (merged weights) |
| Method | Step-level DPO (β 0.1) + 0.5 × SFT on the preferred step; new language-only LoRA r64/α128 merged into the weights (adapter in `lora_adapter/`); vision tower and projector frozen |
| Data | v4.2 decoded its own training rows greedily; where its action was wrong (AndroidControl scorer), the pair is human step (preferred) vs its own step (rejected). Rows with a human `wait` are excluded. No environment, teacher model or benchmark data |
| Phone format | No GGUF published (failed its offline gate; never run on a phone) |
| Status | **Failed its offline gate; not evaluated online.** AndroidControl high-level step accuracy fell from 0.732 (v4.2) to 0.545: whole action types collapsed (`open_app` 0.95 → 0.16, `wait` 0.59 → 0.00, `scroll` 0.62 → 0.16). Kept public as a documented negative result; use v4.2 |

## Input and output

| Part | Format |
|---|---|
| Image | One screenshot per step, resized to at most 880 × 880 px of area (about 720 image tokens) |
| User text | `Goal: …` / `Installed apps: …` / `Previous steps:` (last 8 steps as `n. <intent> -> <action JSON>`, or `None`) / `What is the next action?` |
| Output | `<think>short intent</think>` followed by one compact JSON action; coordinates are integers on a 0–1000 grid |
| Decoding | Thinking on, temperature 0 |

<details><summary>System prompt</summary>

```
You are a phone-use agent operating an Android phone to complete the user's goal.
Each turn you see the goal, the installed apps, your previous steps, and the current screenshot. Reply with ONE next action as JSON.
Coordinates are integers normalized to 0-1000 (x from left, y from top) of the screenshot.
Actions:
{"action_type":"click","point_2d":[x,y]}
{"action_type":"long_press","point_2d":[x,y]}
{"action_type":"input_text","text":"..."}  (types into the focused field)
{"action_type":"scroll","direction":"up|down|left|right"}  (down = reveal content below)
{"action_type":"open_app","app_name":"..."}  (app_name must be one of the installed apps)
{"action_type":"navigate_back"}
{"action_type":"navigate_home"}
{"action_type":"keyboard_enter"}
{"action_type":"wait"}
{"action_type":"answer","text":"..."}  (if the goal asks a question: the final reply, as short as possible and in the requested format; ends the task)
{"action_type":"status","goal_status":"complete|infeasible"}  (finish a goal that asks for no information; never use it instead of answering a question)
```
</details>

## Evaluation

| Offline gate | v4.2 | v4.3-dpo | Threshold |
|---|---|---|---|
| AndroidControl high-level step accuracy | 0.732 | **0.545** | ≥ 0.712 (fail) |
| Terminal `complete` accuracy | 0.738 | 0.885 | ≥ 0.70 |
| dev_answer | 0.868 | 0.875 | ≥ 0.848 |

Cause: 3,039 of the 4,163 pairs were generic wrong clicks/types, and `wait` was only ever the rejected side, so DPO lowered those action types everywhere. The fix is [v4.3-dpo2](https://huggingface.co/alpharomercoma/LFM3-VL-2B-AndroidAgent-v4.3-dpo2).

## Limitations

- Research model. Do not let it act unattended on a phone with real accounts, messages or payments.
- English goals, one screenshot per step, no memory beyond the 8-step text history.
- Not yet evaluated online; it may be worse than v4.2.
