RL operational risks beyond the ranked blockers:

- The four-step smoke measures only three step intervals on the base model, with no periodic save (save_steps=25). Main steps use this estimate, not measured v4 time; `max(10, ...)` can exceed a small budget. The 16,200-second budget covers estimated optimization only, with no wall-clock timeout or reserved eval/upload time. Dead pipelines and failed servers can leave wait loops unbounded.
- `grpo_vlm.py:111–122` says the reload must produce a parseable action, but only prints its first 200 characters and unconditionally emits `RL DONE`. It retains the trainer/optimizer/model while loading a second CUDA model, adding avoidable peak memory; no observed OOM is claimed.
- Configuration filtering can silently discard unsupported parameters after a dependency change; this script neither asserts TRL 1.16 nor records package versions. All relevant fields exist in inspected 1.16 source. It logs reward metrics but never rejects all-equal/all-zero reward groups or excessive truncation. No useful-gradient calibration was demonstrated by CPU inspection.
- Click reward is Gaussian distance to one annotated point, not element membership or action success. Nearby wrong elements get positive reward, alternative valid actions get no credit, and static reward does not establish task completion. `input_text` lowercases/collapses whitespace: all 43 capitalization-bearing texts among 72 actual pool text inputs accept lowercase variants. Some are harmless; synthetic case-sensitive filenames/secrets show the failure mode. Numeric-equivalent `1.50`/`1.5` and `10`/`10.0` get zero reward.
- The RL launcher evaluates five dev splits and AndroidControl but does not run the seed-30 gate or enforce an offline promotion rule. PREREG_v4 requires that rule before RL finishes; no adopted numeric RL rule appears there. AC test uses an unpinned dataset revision. Avoid treating reward gains or `RL PIPELINE DONE` as promotion evidence.
